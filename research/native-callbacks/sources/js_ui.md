# JS engines and script-over-native-UI sources (retrieved 2026-11-09)
- J-S1 RN blog 2024-10-23 (source github.com/facebook/react-native-website/blob/main/website/blog/2024-10-23-the-new-architecture-is-here.mdx): "some updates need to render synchronously in response to user input, potentially interrupting any in-progress render. Since the old architecture was only asynchronous, we needed to rewrite it"; "serializing function calls over the bridge quickly became a bottleneck"; "layout could not be read synchronously, such as reading in a layout effect to update the position of a tooltip."; "JavaScript and the native layer can now synchronously communicate with each other through the JavaScript Interface (JSI), without the need to use an asynchronous bridge."
- J-S2 Hermes jsi.h https://github.com/facebook/hermes/blob/main/API/jsi/jsi/jsi.h IRuntime: "The APIs must not be called from multiple threads concurrently"; HostObject dtor "be called from inside the GC, so it is unsafe to do any VM operations"
- J-S3 RN CallInvoker.h invokeAsync / invokeSync https://github.com/facebook/react-native/blob/main/packages/react-native/ReactCommon/callinvoker/ReactCommon/CallInvoker.h
- J-S4 QuickJS quickjs.texi (github.com/bellard/quickjs master): "Inside a given runtime, no multi-threading is supported."; JS_Call; JS_ExecutePendingJob; JS_SetMemoryLimit, JS_SetMaxStackSize; interrupt handler "regularly called by the engine when it is executing code"; quickjs.c interrupt => "interrupted" uncatchable
- J-S5 JSC JSVirtualMachine https://developer.apple.com/documentation/javascriptcore/jsvirtualmachine "all other threads attempting to use the same virtual machine must wait."
- J-S6 Flutter platform channels https://docs.flutter.dev/platform-integration/platform-channels "messages and responses are passed asynchronously through channels to ensure the user interface remains responsive."
- J-S7 Dart sdk/lib/ffi/ffi.dart NativeCallable.isolateLocal "can only be invoked on the mutator (main) thread of the current isolate. It will abort the process if invoked on any other thread."; listener "only functions returning void are supported. The callback will be invoked at some time in the future."
- J-S8 Flutter merged threads https://docs.flutter.dev/release/breaking-changes/macos-windows-merged-threads "The split-thread design prevented Flutter apps and plugins from using Dart FFI to interoperate with native APIs that must be called on the platform thread."
- J-S9 NativeScript https://docs.nativescript.org/guide/multithreading "JavaScript executes on the main thread (aka the UI thread)."; ios-marshalling "Any API that accepts a block in Objective-C accepts a JavaScript function"
- J-S10 SwiftUI https://developer.apple.com/documentation/swiftui/view `@MainActor @preconcurrency protocol View`; body sync; Layout sizeThatFits(...) -> CGSize sync; Button(action: @MainActor () -> Void); task(_: () async -> Void)
- J-S11 Compose https://developer.android.com/develop/ui/compose/mental-model "A composable function might be run quite frequently, as often as every frame of an animation."; "trigger side-effects from callbacks such as onClick that always execute on the UI thread."; MeasurePolicy measure() sync (androidx MeasurePolicy.kt); LaunchedEffect suspend
- J-S12 Lynx https://lynxjs.org/react/main-thread-script.html "regular JS event handlers can only be executed on background threads... resulting in untimely responses and animations lagging behind gestures." "The main thread script provides the capability to handle events synchronously on the main thread"
- J-S13 Valdi docs/docs/native-bindings.md (github.com/Snapchat/Valdi) "calling a JS function will automatically asynchronously dispatch to the JS thread if needed. If your function need to return a value synchronously to platform code, make sure you call this function within a createScopedJSRuntime scope."
